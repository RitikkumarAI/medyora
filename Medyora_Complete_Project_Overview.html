01 Executive Summary & Problem Statement
Product Vision

Medyora is an all-in-one healthcare super-platform designed to solve India's most critical healthcare delivery bottleneck: the unorganized, time-consuming Out-Patient Department (OPD) queue and fragmented medical record system. In traditional clinics and hospitals across India, patients routinely suffer 2 to 3 hours of idle waiting in crowded waiting rooms without real-time queue visibility, while doctors battle handwritten paperwork, scheduling chaos, and lack of historical patient context.

🚨 The Healthcare Problem in India

• Unpredictable clinic wait times (120–180 minutes average).
• Illegible, lost, or damaged physical paper prescriptions.
• Absence of verified doctor credentials and pricing transparency.
• Language barriers preventing millions from understanding clinical guidance.
• Inability of clinics to balance walk-in patients with online bookings.

✨ The Medyora Solution

• Live Digital Token & Queue Tracker: Know exactly when to arrive.
• Smart Care AI Copilot: Instant 24/7 symptom triage & risk assessment.
• 1-Click E-Prescriptions: Standardized digital Rx with PDF downloads.
• Multi-Persona Architecture: Unified hub for Patients, Doctors, and Admins.
• ABDM & Native Mobile Ready: Ready for Capacitor iOS/Android & PWA.

Platform Stakeholders & User Personas

👤
Patient & Family
Search specialists by symptoms, book in-clinic/video/home visits, track real-time queue tokens, chat with 24/7 AI copilot, manage family profiles, and store lifelong health records.
🩺

05 Database Architecture & PostgreSQL Schema

Medyora uses Supabase (PostgreSQL 14+) with strict typing auto-generated in src/integrations/supabase/types.ts. Every table is guarded by Row-Level Security (RLS) policies and role-checking functions.

Column Type Description

4. profiles & user_roles — Identity & Access Control

User authentication is decoupled into profiles (stores full name, phone number, email, blood group, and emergency contact) and user_roles (stores role mapping patient | doctor | admin). The custom PostgreSQL function has_role(_user_id, _role) verifies authorization in microsecond database queries.

06 Security, Authentication & Storage Architecture
Security & Compliance

Handling medical data demands institutional-grade security. Medyora implements defense-in-depth across the browser, server, and storage layers.

🔐
Enterprise Secure Storage (TTL)
Implemented in src/shared/security/secureStorage.ts. Serializes sensitive session payloads with Base64 encoding, timestamp tracking, and Time-To-Live (TTL) automatic expiration. Stale or tampered tokens are auto-purged on retrieval.
🛡️
Enterprise Security Headers (CSP)
Configured in src/shared/security/securityHeaders.ts and enforced on every SSR response via src/server.ts. Includes strict Content Security Policy, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, and HSTS preloading.

Secure Storage Implementation Snippet

// src/shared/security/secureStorage.ts
interface StoragePayload<T> {
  value: T;
  createdAt: number;
  expiresAt: number | null;
}

export const secureStorage = {
  setItem<T>(key: string, value: T, ttlSeconds: number | null = null): boolean {
    const payload: StoragePayload<T> = {
      value,
      createdAt: Date.now(),
      expiresAt: ttlSeconds ? Date.now() + ttlSeconds * 1000 : null,
    };
    const serialized = JSON.stringify(payload);
    const encoded = btoa(encodeURIComponent(serialized));
    localStorage.setItem(`sec_${key}`, encoded);
    return true;
  },

  getItem<T>(key: string): T | null {
    const encoded = localStorage.getItem(`sec_${key}`);
    if (!encoded) return null;
    const serialized = decodeURIComponent(atob(encoded));
    const payload: StoragePayload<T> = JSON.parse(serialized);
    if (payload.expiresAt && Date.now() > payload.expiresAt) {
      this.removeItem(key); // Auto-purges expired sessions
      return null;
    }
    return payload.value;
  }
};

Role-Based Access Control (RBAC) Workflow

Medyora enforces multi-role authorization at the route layout boundary.

  • Patient Routes (/patient/*): Accessible to standard users. Handles appointment bookings, family profiles, medical records, and AI triage.
  • Doctor Portal (/doctor/*): Guarded by DoctorLayout.tsx. Inspects useAuth().isDoctor. If unauthenticated, displays an interactive clinical verification screen requiring a valid Medical Registration Number (e.g. MCI-74892).
  • Admin Portal (/admin/*): Guarded by has_role('admin'). Grants access to the doctor verification desk, financial audits, and platform settings.

08 Current Limitations & Engineering Trade-offs
Engineering Honesty

To ensure team members know exactly where the project stands today, this section transparently documents current technical boundaries and trade-offs.

Area Current Implementation Status Recommended Production Fix
Database Bridge Supabase types & schema ready, but UI currently relies on rich client stores (mock.ts) for instant local demo capability. Connect real Supabase client queries across all patient.* and doctor.* pages using useQuery hooks.
Video Teleconsultation Frontend video room layout with simulated peer states, camera/mic toggling, and in-call messaging is fully built. Integrate a WebRTC Selective Forwarding Unit (SFU) like LiveKit Cloud or Agora SDK for low-latency multi-peer calls.
Payment Gateway Interactive checkout UI with UPI QR, cards, and netbanking flows is built; transaction success is client-confirmed. Implement server-side webhook signature verification for Razorpay or Stripe in Nitro server functions.
AI Copilot Engine Runs a 270KB+ deterministic heuristic rule engine; fast and zero-cost, but lacks natural language nuances for rare conditions. Bridge with an LLM streaming endpoint (e.g. Gemini 2.5 Flash API) with RAG medical document grounding.
Regulatory Compliance Security headers and TTL storage implemented; official DISHA / ABDM M1-M3 certification is pending. Complete Indian National Health Authority (NHA) ABDM sandbox testing and implement ABHA ID authentication.
09 Future Scalability & Engineering Roadmap
Strategic Roadmap

A 5-phase engineering roadmap designed to scale Medyora from a high-performance prototype to a national healthcare infrastructure serving millions of daily consultations.

Phase 1: Real API & Infrastructure Cutover (Immediate Priority)

• Full Supabase Synchronization: Replace in-memory mock mutations with live PostgreSQL updates via TanStack Query.
• Razorpay Payment Gateway: Integrate server-side order generation and webhook verification for automated doctor fee escrow.
• LiveKit WebRTC Integration: Wire up enterprise-grade encrypted video calls with automatic bandwidth adaptation.

Phase 2: Real-time Pub/Sub & High-Concurrency Live Queue

• Redis / Supabase Realtime Channels: Move token advancement from polling to WebSocket broadcasts.
• Sub-Second Chime Alerts: Ensure immediate synchronization between the doctor's "Call Next" tap and the patient's phone display.
• SMS & WhatsApp Triggers: Auto-send WhatsApp alerts (via Twilio/Gupshup) when the patient is 2 tokens away.

Phase 3: ABDM (Ayushman Bharat Digital Mission) Integration

• ABHA (Ayushman Bharat Health Account) ID: Enable patients to link and verify their 14-digit national health ID.
• M1, M2, M3 Compliance: Implement Health Information Provider (HIP) and Health Information User (HIU) consent managers.
• National E-Prescription Standard: Map Medyora digital prescriptions to FHIR / HL7 compliant JSON payloads.

Phase 4: Multi-Modal Voice AI in Regional Indian Languages

• Voice-First Medical Triage: Integrate Whisper / Gemini Multimodal models for spoken symptom check in Hindi, Marathi, Tamil, and Telugu.
• Doctor Voice-to-Rx: Enable doctors to dictate patient advice; AI transcribes it directly into structured medicine rows and dosages.

Phase 5: Hospital OPD Kiosks & Thermal Printer Hardware

• Receptionist Kiosk Mode: Dedicated touch-screen portal for clinic receptionists to quickly issue paper tokens to walk-in patients.
• Bluetooth Thermal Printers: Auto-print physical token slips with QR codes that patients can scan to track their token live on their phones.
